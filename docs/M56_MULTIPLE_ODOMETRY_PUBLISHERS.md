# Multiple ground-truth odometry publishers

M56 extends the existing Rapier ground-truth OdometryPublisher to zero through eight supported top-level model owners. Each owner retains its existing Odometry, OdometryWithCovariance and transform Pose_V channels, giving at most 24 distinct endpoint leases. Configure distinct topics and frames for every model. Duplicate owners/plugins, invalid configurations and raw or remapped endpoint collisions fail before output declarations.

[The example](../examples/m56_multiple_odometry_publishers.sdf) contains a planar owner at 50 Hz and a spatial owner at 25 Hz with existing local/global translation and rotation offsets. It adds no wheel estimator or sensor. Positions and velocities derive from the same existing model-pose history. Planar and spatial frame conventions, first-sample transient, ten-sample means, covariance representation and noise behavior are unchanged. This is development Source, pending complete verification and release qualification.

Each owner keeps separate publication clocks, history and ID-seeded noise state. Acquisition advances without subscribers, including history and configured noise draws before rate throttling. Disconnecting or adding a peer does not reset another owner's state. Paused updates, inclusive time suppression, direct-core reset and loaded-world reconstruction retain their previous behavior. Removing the final owner retires the family's callbacks and endpoints; a supported loaded reset reconstructs original owners with stable IDs and new entity handles.

A failure retains the existing global terminal-step behavior. Callbacks after an earlier fault may not run; already processed peers need not roll back, and cached samples are not promised to clear. A terminal reset remains refused. There is no new per-owner fault isolation or deterministic owner-update order.

The server validates original, current and prepared identity, full scoped names and every resolved channel key before IO. Reset preparation uses original blueprint settings while validating the complete current set, retaining existing valid numeric-drift restoration controls; stream installation still checks exact immutable configuration equality. Valid manual singleton compatibility is retained when no loaded initial scene exists; manual multiplicity is not added. All neighboring publication families, including removed loaded originals, retain their reserved endpoints and typed collision rules.

The bound does not expand supported model nesting, backends, plugin loading, metadata, frame/noise domains or transport. The fresh reference directly links the unchanged original OdometryPublisher object into a new owned helper; capture, independent native DATA, immutable export and independent fixed-literal DATA passed separately. It preserves complete finite LOCAL/WORLD/getback inputs and Info, fences and actual Odometry/OdometryWithCovariance/Pose_V fields, Header presence, f32 covariance words and canonical wire bytes. Native order is retained; no expected output is estimated or reencoded. The rejected original DSO and both failed attempts remain failed.
