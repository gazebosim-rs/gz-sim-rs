# M14: bounded local STL meshes

M14 is an independent increment over accepted M12, developed alongside the ideal
altimeter M13. The two features share one candidate and serialized qualification,
not each other's implementation. Follow [POST_MVP_DELIVERY.md](POST_MVP_DELIVERY.md)
for file ownership and mandatory review/check boundaries. Source authoring alone
does not establish a passing candidate or acceptance.

## Admitted geometry

An SDF mesh may name a local lowercase `.stl` file, relative to its local SDF
source or through an existing admitted file URI. The bounded ASCII path and
canonical resource-directory/symlink rules remain in force. Network and Fuel
resolution, submesh selection/recentering, optimization/decomposition and embedded
color/attribute payloads are outside this increment. No original source or remote
resource is rewritten or downloaded.

`gz-assets` uses pinned maintained `stl_io` 0.11.0 triangle iteration. The eager
unbounded indexed-reader convenience API is not used. Input is at most 16 MiB,
with at most 262144 triangles and 131072 unique vertices. Indices are constructed
incrementally from exact f32 coordinate bits with signed zero normalized; no
approximate welding, count-based reservation, face deletion or topology repair
occurs. Repeated vertices do not consume the unique-vertex budget. All coordinates
and supplied normals must be finite. Every triangle must have representable,
nonzero f64 area before and after positive finite SDF scale.

Binary STL must have exactly `84 + 50 * triangle_count` bytes and zero attribute
words. Binary headers are arbitrary, including headers starting `solid `. A
bounded decoder-only copy masks the ignored first header byte to select the
maintained binary reader after exact-length validation; original bytes are
unchanged. Other inputs use the maintained ASCII facet grammar, with a resource
limit of 2048 bytes per line and one `endsolid` as the last nonblank line. This
envelope closes the upstream reader's stop-at-first-terminator behavior, refusing
trailing/concatenated documents rather than ignoring them. Empty geometry refuses.

STL coordinates are Z-up, with units supplied by the file/SDF scale convention;
the format itself declares no units. Scale applies exactly once. The existing
Rapier admission remains authoritative: static triangle surfaces may be open;
dynamic meshes must already be closed, connected, outward and convex, with at
most 512 distinct vertices and 1024 triangles. No hull approximation is added.
Other backend capabilities do not change merely because another format decodes.

## Maintained viewer and immutable resources

Collision loading and visualization share `gz_assets::mesh::decode_stl`.
The CLI asset boundary calls `stl_visual_glb` and captures one self-contained
generated `.stl.glb` route per canonical source document. Captured model metadata
retains the original STL URI and scale. Multiple visual instances share the
unscaled captured geometry; their existing Scene transforms/scale remain separate.

The generated GLB rotates Z-up positions into glTF Y-up. The accepted maintained
viewer reverses that basis through its existing glTF lane; scale remains the SDF
scale rather than being baked into both buffers and visual metadata. Normals are
recomputed from actual winding using area-weighted incident face normals. Exact
cancellation uses the first incident nonzero face normal deterministically. This
affects shading only, not the supplied surface or winding. No new viewer loader,
protocol, dependency, UI, renderer or production Wasm build is introduced.

Indexed positions/normals and u32 indices stay bounded at the full input geometry
limits. Generated output must remain below the existing 16 MiB file limit and
counts against the unchanged 128-resource/64 MiB captured-resource budgets. Raw
STL is not a second served asset. Captured generated bytes survive source edits,
deletion, runtime-alias retirement and server ownership transfer. Recording/replay
continues to admit the same immutable glTF resources and existing route scopes;
there is no STL archive schema or new replay parser.

## Regression and actual evidence requirements

The new asset controls cover equivalent ASCII/binary asymmetric tetrahedra,
`solid` binary headers, scale/basis round trips through the maintained glTF parser,
normal cancellation, malformed/truncated/trailing/color/nonfinite/degenerate
input, independent face/unique-vertex bounds, signed zero and existing path/options
refusals. CLI controls exercise actual immutable HTTP GLB bytes, original metadata,
shared document ownership, alias retirement, recording admission and atomic
resource-budget refusals. Scene controls exercise native f64 analytic ray hits,
open-surface contact, removal/reset after original-file deletion, and admitted
dynamic convex construction/free fall with open-dynamic refusal.

`examples/meshes/m14-asymmetric-ascii.stl` and
`examples/meshes/m14-asymmetric-binary.stl` are original small fixtures describing
the same outward tetrahedron with extents 1, 2 and 3. Their nonuniform geometry
distinguishes basis errors from scale errors. Root owns the combined runnable
example and central test attachments; this document does not preclaim execution.

After complete feature/regression/docs and independent Source review, one normal
combined mandatory gate and exact CI retain all strict coverage/assertions.
Actual browser evidence must show the asymmetric STL-derived visual and physical
motion, followed by existing Pause/Reset controls. Images establish visible
behavior, not numerical odometry, pixel geometry, universal format compatibility
or performance. Preserve accepted M1–M12 proofs; they are not replayed here.
