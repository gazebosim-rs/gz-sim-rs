# M10: focused interactive world lifecycle

Implementation is in progress; M10 is not accepted. M1–M9 remain accepted.
The phase budget is at most five working days including independent review and
required checks. Root owns Scene/Server/CLI integration; viewer and physics work
use isolated M10 worktrees. Complete the whole source/regression/documentation
batch and independent review before consolidated required verification.

The admitted editing domain is one Rapier world with standalone, single-link,
single-body primitive or admitted local glTF models, no joints, nested models,
sensors or other system ownership. Existing controller models cannot be edited
through this path. Reuse current spawn, removal, IDs and resource admission.
Never rebuild/reset unrelated bodies to implement an operation. Explicit user
state replacement is a world-edit operation, not an actuation shortcut.

## Selected opt-in contract

The server enables editing explicitly with --web-lifecycle alongside
--web-viewer. The primitive viewer selects lifecycle=1; its WebSocket connection
also requests lifecycle=1. Existing scan=1 remains independent. Default Gazebo
and primitive protocols, Scene v1/v2 payloads and existing control ACKs are
unchanged. No lifecycle catalog/state/command ownership exists without the
configured capability. Missing capability keeps editor controls disabled.

The server prepares a bounded catalog of declared templates outside stepping.
Only declared templates can spawn: no XML, filesystem path, arbitrary URI or
remote download is accepted from a browser. Mesh bytes use the already admitted
immutable local glTF resource domain. Runtime mesh visual aliases must be
validated before native/ECS commit; no filesystem/network/GPU wait belongs in
critical stepping. Template and asset limits preserve the existing 128-visual,
64-KiB publication and local-resource bounds.

Every lifecycle message uses version 1. Identifiers are nonzero Rust u64 values;
visual IDs must additionally satisfy the existing rendering-ID admission.
The server sends kind=lifecycle_catalog with world_id, epoch, scene_sequence,
templates [{template_id,label}] and models
[{model_id,name,visual_ids,can_remove,can_set_state}]. Model-to-visual ownership
is authoritative. Catalog models have nonempty, disjoint visual-ID sets; invisible
models are outside this focused phase. There are at most 128 templates, 128 models
and 128 total owned visuals, with the independent 64-KiB encoded limit retained.
Never infer model IDs from flat visual IDs or names.

A client sends kind=lifecycle, request_id, world_id, epoch and one action.
The action is a snake_case string field with its variant fields as siblings;
unknown or inapplicable fields are refused:

- spawn: template_id, translation [x,y,z], rotation [x,y,z,w].
- remove: model_id.
- get_state: model_id.
- set_state: model_id, translation, rotation, linear_velocity [x,y,z],
  angular_velocity [x,y,z].

The pose is the model/canonical-link origin in world Gazebo Z-up coordinates.
Only identity local link frames are admitted. Linear velocity is world velocity
of that origin; angular velocity is world rad/s. Scene converts to/from the
native COM velocity using the current/requested rotation and stored COM offset.
No viewer basis conversion is applied on the wire; existing rendering conversion
occurs once. Finite pose, unit quaternion, native bounds and rendering
representability must be validated before mutation. Fixed bodies require zero
velocities, and every joint participant is explicitly refused.

Spawn names are generated by the server; clients do not provide names.
All actions share the existing strictly increasing request-ID allocator and ONE
pending-command slot with pause/resume/reset. Requests carry an expected world
and epoch; stale requests are refused before mutation. Each valid command is
bounded by the existing 4-KiB input, eight-slot server queue and per-iteration
budget. No automatic retry of a mutation follows disconnect or unknown outcome.

The reply kind=lifecycle_ack carries request_id, action, world_id, epoch,
scene_sequence, seconds, nanoseconds, paused, ok, error, model_id and state.
A successful spawn/remove returns its created/removed model_id and null state.
A successful get/set returns the requested model_id and actual committed state.
Every refusal returns null model_id and state. State, when present, contains
translation, rotation, linear_velocity and angular_velocity in the convention
above. Error text is bounded and must not expose private resource paths.
Ordinary refusals leave native/ECS state and published identities unchanged.

## Commit and client fences

The server captures the unchanged full Scene plus catalog/state reply from the
same committed publication. Scene.sequence, not epoch/time alone, binds side
payloads because paused edits can share timestamps. Send the full Scene before
its catalog/reply; the client admits a reply only after its matching Scene
sequence. Preserve the independent measured-scan fence/resource.

Successful UI scene changes derive only from full Scene publications, never
optimistic local insertion/removal or poses. Clear lifecycle state, selection and
pending outcomes on reconnect, epoch/world replacement or capability loss.
Selection is a catalog model ID rebound through the authoritative visual map
after rendering entities are replaced. Unknown outcomes require a fresh snapshot
and user inspection; mutations are not silently resent.

A minimal separate full-UI panel offers template spawn, selected-model removal,
and explicit read/apply pose and velocity controls. Reuse existing panel and
number/text widgets; keep generic Gazebo edit capability disabled for the
primitive backend. Both existing 14-MB release bundle gates remain unchanged.

## Required acceptance

Prove real native/ECS spawn and removal of primitives and one local mesh,
state-frame/velocity behavior, stable IDs without stale visuals, bad/stale/
overload atomic refusals, pause/reset and reconnect snapshot replacement.
Verify default/no-opt-in negatives, existing control/scan behavior and native-
free/GPU-free headless defaults. Observe actual browser operations after the
complete required local gate, exact hosted CI and independent evidence review.
Multiworld, levels, distributed stepping, arbitrary SDF imports and general
articulated editing remain excluded.

## Running the bounded demo

Build the normal headless CLI and the gzweb-rs full viewer after qualification.
Run `examples/m10_world_lifecycle.sdf --server --web-viewer 9010 --web-lifecycle`
with `target/debug/gz-sim-rs`. It starts paused. Serve the viewer on the supported
HTTP port 8080 or 8081 and open
`?backend=primitive&ui=full&lifecycle=1&url=ws://127.0.0.1:9010/`.
The lifecycle panel lists only the loaded ground, box, sphere and local-mesh
templates. Choose a template and a world pose to spawn it. Select a model by its
catalog identity, read its state before applying pose/velocity changes, or remove
it. Play/pause/reset retain their existing controls. Reset restores the loaded
world and retires runtime additions; reconnect obtains a full current snapshot.

The template catalog never accepts browser XML, file paths or downloads. Mesh
visual bytes and routes are captured at startup and remain valid when the source
model is removed. Runtime visual aliases refer only to those declared bytes and
retire on removal/reset. Mesh collision admission uses the existing static
triangle-mesh/dynamic-convex-only policy, with no hull approximation. General formats, new resources, nested
models, joints/sensors on edited models and camera-owned mutable scenes remain
outside this delivery. Canonical pose publication observes edits on the next
normal server tick; the local browser gets the committed full Scene immediately.

The new CLI dependency edges reuse the already pinned workspace `bevy_ecs` and
`gz-physics` packages. Server regression controls add only a dev dependency on
the same physics package. No upstream version, transport implementation, feature
gate, coverage threshold or release bundle budget changes.

## Scene implementation boundary

The current Scene source prepares clone templates at startup from the same
resolved SDF model used to load the scene. A template retains the original
collision, inertial frame, visual pose/material and declared mesh identity.
Template preparation may decode a declared mesh; runtime spawn performs no XML
parsing or resource lookup. Primitive templates use the existing centered
box/sphere native admission, and mesh templates use the accepted mesh adapter.
Templates belong to one Bevy world and its retained native owner.

Spawn preflights four monotonic public IDs, the viewer's ID range, generated
names and representable poses before native admission. ECS identities commit
after native acceptance. External observers that corrupt those exclusive-world
invariants cause a terminal invariant failure rather than an ordinary atomic
refusal. The bridge must additionally preflight its catalog and immutable asset
alias before calling this API. Runtime additions preserve unrelated bodies and
the loaded reset blueprint; loaded reset removes additions without recycling
their IDs. Explicit fixed-body pose edits acquire a model anchor so ordinary
reset also restores the model origin correctly.

State reads validate the public-link/native-body ownership pair and convert
fresh native COM velocity to origin velocity. State writes preflight numeric,
native and attached-visual bounds before replacing one body's state. No physics
step, collision-cache refresh, actuator command or unrelated-body reset is used.
These Scene slices and their regression source are still unqualified until the
complete CLI/bridge integration, independent review and consolidated gates pass.

The bridge applies lifecycle edits after the current tick and its remote-control
preparation. It then publishes a new full Scene and matching catalog/ACK at a
new sequence. This places world/epoch validation after any reset accepted during
that tick. Paused edits may share a clock time while differing in Scene sequence,
which is why the side-channel fence is mandatory. The first lifecycle delivery
refuses camera-owned world edits and the CLI combination with `--camera-worker`.
Mutable renderer-scene admission is deferred; existing RGB/depth worlds and their
headless defaults retain their accepted behavior.
Existing measured sensor samples retain their own acquisition time; an edit
does not synthesize a new scan or replay a committed acquisition.

## Bounded publication credit (correction in progress)

The first candidate passed required local and hosted checks, but its actual
browser qualification failed. The separately qualified diagnostic viewer then
recorded `event queue full; requested close 4002` (the close event reported
1006). Passing CI did not accept M10. The original sources, failed observations
and qualification evidence remain preserved.

Lifecycle viewers additionally negotiate `lifecycle_credit=1` together with
`lifecycle=1`. The producer sends one normal coherent Scene, catalog and optional
scan, followed by `{"version":1,"kind":"publication_credit","token":1}`.
It retains the existing bounded Latest state rather than flooding a stalled
consumer. Only the exact `{"version":1,"kind":"publication_ready","token":1}`
allows the next normal publication. Tokens are nonzero, checked, monotonically
increasing and connection-local; disconnect resets them, world reset does not.
Both envelopes have exactly those three fields. Duplicate, stale, malformed or
unnegotiated credit is refused.

Ready acknowledges validated inbox admission, not GPU completion or a world
operation. Its parser runs before the pending-command guard and never consumes
a world request ID, pending-command slot or simulation queue entry. The socket
still services commands and Ping while normal publication waits. Committed
lifecycle frames and control ACKs retain their priority and exact ordering;
they neither consume nor replace an older outstanding normal token. The viewer
keeps validated transport credit across same-connection reset clearing, sends it
once after successful flush, and closes on bounded send failure without retry.

No extra simulation wait, worker, endpoint or callback is introduced. Existing
no-credit clients, 64-event queue/drain, frame limits, ingress bounds, assertions
and quality gates remain unchanged. New regression source covers strict tokens,
query negatives, real socket producer backpressure during paused/running native
worlds, pending commands, exact delayed replies and reset interleavings. This
correction is unqualified until its complete source review, required checks and
actual browser acceptance finish; no behavior pass is claimed from source alone.
