# M60 installed preview: capability boundary

M60 is a Source-only preparation of the current native-free Ubuntu 24.04 x86_64
preview. Final integration depends on actual M59 normal and retained DATA. No
M60 build, ELF closure, package, clean installation, browser or release pass is
reported here; M40 remains the installed Latest until actual promotion gates pass.

## What the selected payload must contain

Preserve the complete default M19 robot, three existing executables and launcher,
both immutable accepted WebGPU/WebGL2 viewer flavors, both 14,000,000-byte gzip
budgets, notices and exact manifest/archive inventory. Source-bound release
artifacts use locked no-default-features builds without rgb-camera. Installed
runtime is intended to need ordinary OS libraries and Python, not Cargo, a
compiler, Gazebo/DART/MuJoCo SDK, camera worker or checkout. Actual current dynamic
closure and clean installation must prove that intention; old evidence cannot
silently qualify new binaries.

The package extends the unchanged 18-example M21–M43 prefix with exactly 15 M45–M59
fixtures, totaling 33. There is no invented M44 example. The new copies cover
custom-world/heading IMU, odometry offsets/noise, independent sensor and publisher
owners, two joint-controller chains and two differential-drive robots. All
original per-system domain limits, source-informed reference boundaries,
tolerances, math and unsupported cases remain. Loading for two steps does not
prove a sensor acquisition, RNG parity, canonical message, motor response or
original Gazebo System equivalence.

The M59 example has actual duplicated M8 robots at Y=-2/+2, four canonical
command/odometry routes and distinct frame pairs. The viewer adds no telemetry
widgets. `run --example` chooses only a manifest-listed SDF basename; omission
keeps the default. `drive --topic` selects a concrete canonical command route;
omission keeps the M8 topic and four existing sender positional arguments.
These options use existing transport/processes and no new framework or IO worker.

## Preserved restrictions

Rapier f64 remains authoritative; this package does not add native backend
features, motor/solver changes, new topology, sensor domains, dynamic plugins,
remote resources or a transport adapter. Odometry is measured encoder output,
not commanded velocity multiplied by time or slip-free chassis ground truth.
Selected reference feature evidence stays explicitly inherited; no fresh original
DiffDrive campaign, SDK provider rebuild or trajectory parity is supplied.

The existing loopback port restrictions, manifest file hashes/modes, owned child
shutdown, missing/tampered input refusal, full license/notice closure and relative
mesh copies remain required. Lifecycle mode is still explicit: the native
--web-lifecycle flag must match the printed lifecycle=1 viewer query. It preserves
the existing supported spawn/remove/state catalog, without making articulated
robots newly editable or granting physics changes.

M60 acceptance requires full Source/regression/docs review, batched corrections,
consolidated formatting and the unchanged full normal/strict coverage plus
independent retained DATA; then actual source-bound packaging, clean relocated
installation, current robot commands/browser controls and owned shutdown with
independent retained evidence. Accepted predecessors, exact hosted CI, official
DATA and ordinary Main/release/Latest readbacks still govern publication. The
owner's requested closeout date is a target, never a quality waiver.
