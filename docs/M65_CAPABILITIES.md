# M65 fleet preview capability boundary

M65 is Source preparation on accepted Main
`192ede6369ab6d83ecf88230944d2061f74b5e94`: M1–M64 and 197 slices are accepted.
The repository records this boundary in `docs/M61_M64_ACCEPTANCE.md`. The single
affected formatter passed; no M65 test, build, installed command, browser or
release result is claimed.
M60 stays Latest with 33 installed examples. Successful M65 full local normal
and independent local DATA are prerequisites to same-head LOCAL PROVISIONAL
distribution work. All hosted/official/Main and fresh distribution proof gates
remain required before acceptance, public release or Latest.

## Selected payload

The M65 generation copies the unchanged 33 M21–M59 examples in order and appends
only `m61_eight_diff_drives.sdf` and `m62_eight_joint_controllers.sdf`: 35 installed
examples. The Source qualifier has 37 examples, including camera fixtures; that
is a different registry and does not imply an installed RGB-worker capability.
M44/M60 package generations keep their original guide selection and 33-entry
registry. Their old guides and evidence are historical and are not relabeled.

Preserve the complete default M19 robot, three actual native-free release ELFs,
manifest-bound `run --example`, `drive --topic`, and the direct joint helper's
optional trailing `--topic`. With that option absent, joint mode defaults and
finite position/velocity/force semantics remain exact. The guides explicitly set
matching `GZ_PARTITION` and the endpoint; no launcher joint-command mode is added.
Preserve six accepted viewer files, both 14,000,000-byte gzip budgets, notices,
source/compiled-package identity, ELF/dependency closure, exact manifest
hashes/modes, both M33 relative mesh copies and safe archive relocation.

Eight loaded M8-domain differential-drive robots keep their math, limits,
canonical Twist/Odometry, measured encoder frames and aggregate command budget.
Eight loaded M9-domain controller chains keep two selected joints each, sixteen
canonical Double inputs, per-stream budgets and original reset/removal rules.
No manual multi-controller admission or new topology is introduced. Position is
an existing Rust servo, not native ABS/PID or trajectory equivalence. Motor
commands and measured encoder motion are not hard chassis-speed guarantees.

## Required fresh proof and explicit exclusions

Two one-millisecond finite steps prove loading/stepping only, not acquisition,
noise, command application, demand, cadence or physical response. After complete
Source/regression/docs review, require successful full local normal/strict
accepted-parent coverage and independent local DATA. The exact same qualified
head may then enter LOCAL PROVISIONAL distribution work while its own hosted CI
runs: rebuild the actual three release ELFs, collect current dependency and
notice closure, and independently audit the archive and relocated installation.
Local heavy work stays serial. A changed head invalidates this same-head basis;
no earlier candidate result or premature acceptance/publication is transferred.
A clean supported non-root Ubuntu runtime without checkout, compiler or physics
SDK must exercise all 35 installed examples. The actual installed demonstration
must address eight drive owners and all sixteen controller routes, retain real
scoped physical/target/application/sample and isolation evidence, show fresh
browser Play/Pause/Reset, and prove owned process/listener shutdown. Discovery,
successful publication and helper exit alone do not meet those obligations.
Independent retained DATA must precede Main/tag/release/Latest readbacks.

There is no RGB/depth worker, GPU/software-renderer bundle, SDK/provider bundle,
new viewer build, backend, solver, protocol or transport framework. Do not pass
`--camera-worker` to this no-feature simulator. Camera/cylinder implementation
proofs do not distribute those runtimes. No Ogre/native-System, trajectory,
performance or broad compatibility claim is made. M60 assets/Latest stay intact
until the new release actually passes every publication gate. Historical reboot
losses and unknown process exit limitations remain disclosed in retained evidence;
new proofs must not silently reuse or reconstruct lost originals.
